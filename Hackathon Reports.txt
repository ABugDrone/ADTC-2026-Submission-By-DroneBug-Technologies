# Technical Report — BusinessPilot AI

**Team:** DroneBug Technologies
**Track:** Africa Deep Tech Challenge 2026 — Laptop LLM
**Domain:** Corporate Enterprise
**Model:** tiny-aya-earth Q4_K_M (3.35B)
**Languages:** English, Hausa

---

## Problem

African SMEs and entrepreneurs face three challenges: (1) unreliable or expensive internet that blocks cloud SaaS tools, (2) limited access to AI business intelligence without cloud subscriptions, and (3) the administrative burden of task scheduling, financial tracking, and data analysis on resource-constrained laptops. BusinessPilot AI solves this as a complete offline business assistant running entirely on an 8 GB RAM laptop with no GPU, no internet, no cloud dependency — and supports both English and Hausa.

Target users: micro-entrepreneurs, SME owners, accountants, and operations managers across Africa who need AI-enhanced scheduling, financial modeling, CSV data analysis, document Q&A, and bilingual support — all running locally on a Lenovo T450-class machine.

---

## Architecture Evolution

The project went through three iterations:

1. **Gradio** (initial) — Heavy, slow load times, complex dependencies.
2. **FastAPI + Alpine.js + Plotly** — Removed Gradio but still required a Python backend with pandas, plotly, sqlite-vec, etc.
3. **Pure client-side HTML** (final) — Single `index.html` talking directly to `llama-server.exe` on port 8083. No Python runtime needed for the frontend. All data persists in browser localStorage.

This final architecture is the leanest possible: a native C++ binary for AI + a static HTML file for UI.

---

## Design Decisions

- **Base model:** tiny-aya-earth (Cohere2 architecture, 3.35B, GGUF Q4_K_M). Chosen for its strong multilingual ability (English + Hausa), small footprint, and instruction-following quality.
- **Quantization:** Q4_K_M gives the best quality-to-RAM tradeoff for a 3.35B model on 8 GB RAM.
- **Runtime:** llama-server.exe (b9895, Windows CPU build) — ADTC-compliant, no GPU required.
- **Frontend:** Single HTML file with embedded CSS and JS. Chart.js for charts, PapaParse for CSV, marked.js for Markdown rendering. All three libraries bundled in `static/libs/` for offline use.
- **No backend server:** The frontend calls `llama-server` directly via its OpenAI-compatible API on `127.0.0.1:8083`. CORS is enabled via `--ui-mcp-proxy`.
- **Notifications:** Browser Notification API fires native Windows toasts. No Python, no polling.
- **Persistence:** localStorage stores tasks, chat history, and knowledge base chunks across sessions.
- **Bilingual support:** System prompt tells the model to reply in the same language (English or Hausa). No separate language detection needed.

---

## Constraints

- **Hardware:** Lenovo T450, 8 GB RAM, Intel Core i5-5300U (2 core/4 thread), no GPU
- **Memory budget:** ~2 GB for llama-server + model, ~150 MB for browser, ~50 MB for Python HTTP server = ~2.2 GB peak
- **Connectivity:** Fully offline during inference
- **Power:** Q4_K_M reduces memory bandwidth and CPU load for battery-conscious operation

---

## Benchmarks

Observed on Lenovo T450 (i5-5300U, 8 GB DDR3, Windows 10, CPU-only):

| Metric | Value |
|--------|-------|
| RAM at peak (server + model) | ~2.1 GB |
| Model load time | ~50 s |
| Prompt processing | ~18 tok/s |
| Generation speed | ~4 tok/s |
| Thermal throttling | None (sustained 60-65 °C) |
| Frontend cold load | Instant (<1 s, static file) |
| Chat response (256 tokens) | ~60-90 s |

Note: Generation is CPU-bound on the T450's dual-core i5-5300U. A modern laptop with higher single-core frequency would see 2-3x faster generation.
